# aire validation

The test suite distinguishes format fixtures, MCP and provider protocol tests, actual
toolchain integration, and Agent-quality evaluation. Passing one category does not
imply the others passed. The primary workflow uses an external Agent over local
stdio MCP; standalone `ask` is an optional provider-backed path.

## Local verification on 2026 10 16

The complete suite passed with **140 tests and no skips**, with Xcode fixture builds
and real Ghidra integration enabled. Ruff and the packaged skill's structural
validator passed. The Python wheel distribution was also built successfully.

The tested toolchain was Python 3.14.3 x86_64 through Rosetta, Ghidra 12.1.4,
PyGhidra 3.1.0 and Corretto JDK 25, with Ghidra macOS native tools built locally.
Ghidra imported both the regular and stripped arm64 iOS demo, discovered 192 functions
and exported 22 ObjC methods. Both `saveFavorite:` implementations remained candidates.
A real `FavoriteStore` decompilation contained the NSUserDefaults write and storage key.

Automated tests did not run the iOS application or call a live model endpoint.
Provider protocol tests use local test servers. HTML content and injection behavior
were checked automatically; interactive browser rendering was not verified in this
environment.

The exact project-local Codex configuration generated by `aire setup` was also
launched with aire model configuration absent. Its MCP handshake succeeded and
exposed 18 tools. This checks the generated launch command and tool discovery; it
does not establish that an already-running host session has reloaded configuration.

## Independent MCP investigation trial

An independent Agent followed the packaged `aire-investigate` skill and used the
official MCP Python SDK to investigate the stripped demo IPA. The evaluator did
not read the demo source, expected answers or prior investigation conclusions. It
used the actual Ghidra backend, with no separate model API configured or called by
aire and without executing the iOS application.

For case `case_7608b59d6c0248dc`, the investigation retained 24 tool evidence results
and saved 11 cited claims with zero citation demotions. Its static explanation
identified NSUserDefaults save/load behavior using the key `aire.favorites.v1`,
and retained both declared `saveFavorite:` implementations as dispatch candidates.
The saved status remained `partial`, with `semantic_correctness_verified=false`.
Unresolved button/selector pairing, runtime receiver identity and actual device
persistence were recorded as limitations rather than treated as verified behavior.

The local report is at
`.aire/mcp-forward-test/reports/case_7608b59d6c0248dc.md` (not included in the
distribution). Input SHA-256:
`508c3c3fbd55eb60f67b21ed7861be27cb5e608467bbc50d5bc37a9be5c98564`.
This was one independent Agent trial on a small controlled sample, not a benchmark
success rate, a comparison across models or proof of general investigation quality.

## Automated checks

- Malformed and hostile archives, duplicate paths, symlinks, size limits and source immutability.
- Thin/fat Mach-O metadata, absolute evidence offsets, encryption exclusion and ObjC method formats.
- Project isolation, Chinese substring search, evidence persistence, deletion and deterministic replay.
- CLI import, offline investigation and report export; HTML and Markdown injection handling.
- Actual stdio MCP handshake, discovery, import/case/evidence/findings/export lifecycle,
  status propagation, argument validation, stdout isolation, bounded responses and shutdown.
- Case evidence isolation, saved findings validation, worker eviction/deadlines, and
  model-free investigation persistence without exposing standalone model conversations.
- Project-local setup previews, idempotence, path quoting, toolchain-only environment,
  preservation/backups of existing configuration, and refusal to overwrite unrelated files.
- Model tool-call protocol, bounded retries, budgets, follow-ups, malformed reports and fabricated citations.
- Ghidra protocol errors, missing dependencies, process lifecycle and opt-in actual decompilation.

## Genuine iOS sample

`examples/build_ios_demo.py` compiles a UIKit/Objective-C app with Xcode. Its unstripped
and stripped binaries provide realistic inputs for inventory and Ghidra. Tests and
scripts never run the app or send its demo network request.

The benchmark records known implementation anchors and expected unknowns. It includes
same-selector ambiguity and a server-side behavior question that cannot be answered
from the IPA. Expected answers must never be sent to the investigation model.

## Agent-quality evaluation

Before claiming a success rate, fix the sample hashes, toolchain, model, prompt version
and budgets. For an external Agent, also record the host and skill version. For each
question, record the actual output and manually assess:

1. Whether the correct entry appears among the candidates.
2. Whether the important implementation steps are correctly explained.
3. Whether each factual claim is supported by its cited evidence.
4. Whether dynamic/remote/unsupported behavior remains explicitly unknown.
5. Runtime, tool-call count, token use and repeated-run variance.

The planning target of 70% useful investigations remains a target until a sufficiently
representative, independently reviewed evaluation has been recorded. The single MCP
trial above does not establish that target; v0.1 does not claim it has been achieved.
